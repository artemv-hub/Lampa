# AGENTS.md

Правила для будущих правок в этом репозитории. Соблюдать всегда, если явно не сказано иначе.

## Контекст проекта

- Плагины работают в приложении **Lampa** — https://github.com/yumata/lampa-source
- Плагины работают с бэкендом **Lampac** — https://github.com/lampac-nextgen/lampac
- Каждый плагин — отдельный самодостаточный `.js` файл в корне репозитория.
- Учитывать API Lampa (`Lampa.*`) и поведение Lampac при написании кода и при проверке совместимости.

### Синхронизация

- **CUB не используется вообще.** Не предлагать решения через CUB и не искать там данные.
- Вся синхронизация идёт **через Lampac**.

## Отступы

- Отступ — **2 пробела**. Табы не использовать.
- Перенос длинных строк — с отступом +2 пробела от текущего уровня.

## Стиль кода

Стиль как в существующих плагинах этого репозитория (`favoritePlus.js`, `interfaceBadge.js`, `interfaceMobile.js`, `interfaceStyle.js`, `torrentPreload.js`). Перед правкой смотреть соседние файлы и повторять их манеру.

- Весь файл — IIFE со строгим режимом:
  ```js
  (function () {
    'use strict';

    // ...

  })();
  ```
- В начале файла — блок `manifest`:
  ```js
  const manifest = {
    type: 'interface',
    version: '5.2.4',
    name: 'UI Badge',
    component: 'ui_badge'
  };
  Lampa.Manifest.plugins = manifest;
  ```
- Точка с запятой в конце инструкций.
- Строки — одинарные кавычки; шаблонные литералы — только для многострочного текста/CSS.
- Стрелочные функции для колбэков и коротких хелперов.
- Короткие проверки в одну строку: `if (!item) return;`
- Пустая строка между логическими блоками и между методами объекта.
- Без лишних комментариев: комментарий только там, где неочевидно.

## Комментарии

- Секции кода помечать комментарием ЗАГЛАВНЫМИ буквами, например:
  `// STORAGE`, `// FAVORITE`, `// STYLES`, `// MAPS`, `// PATCH`, `// PRELOAD`, `// BAR`, `// SIZE`, `// FULL`, `// BUTTONS`, `// TITLE`, `// INIT`.
- Технические комментарии — на английском, кратко.
- Пользовательские строки (тосты, ошибки, подписи) — на русском.
- Не дублировать в комментарии то, что и так ясно из кода.

## Именование

- Функции и переменные — `camelCase`.
- Константы уровня модуля — `UPPER_SNAKE_CASE`, например `STORAGE_KEY`, `STORAGE_SYNC_KEY`, `BAR_ACTION`.
- Карты/справочники — с префиксом `map`, например `mapQuality`, `mapStatus`, `mapVote`, `mapPG`.
- Приватные поля и методы объекта — обычным `camelCase`, без подчёркивания, например `data`.
- Имена осмысленные, без сокращений-загадок; доменные имена Lampa (`Lampa.Storage`, `Lampa.Listener`, `Lampa.Platform`) не переименовывать.

## Версионирование

- При изменении плагина поднимать `version` в его `manifest`.

## Тестирование фиксов

### Как тестирует пользователь

- Плагины тестируются в локальном `test.js` — в него просто подставляется новый код.
- Отдельные файлы под тест не создавать, промежуточные файлы в репозитории не оставлять.
- Основная проверка — на ПК, но пользователь работает и с других синхронных устройств, поэтому порядок должен совпадать везде.
- Обратная связь — вывод консоли из приложения. Решение искать по нему, а не наугад.

### Как выдавать код

- Код плагина писать прямо в ответе чата.
- Одновременно подключён **один** плагин: сначала дебаг-плагин, потом исправленный. Не смешивать дебаг и фикс в одном файле.
- Перед проверкой фикса всегда давать обновлённый дебаг-плагин с нужными выводами в консоль.

### Порядок работы

- Цикл: **дебаг → фикс → проверка → и по кругу**, пока не заработает.
- Пользователь сначала подключает дебаг-плагин, смотрит поведение, потом ставит исправленный плагин. Если нужно — снова через дебаг-плагин.

## Git и коммиты

- Коммитить и пушить **только в `main`**. Ветки не создавать, PR не открывать.
- **Не коммитить и не пушить без явного подтверждения пользователя.** Сначала внести изменения в рабочую копию, дать пользователю протестировать; коммит и пуш — только после его подтверждения.
- Сообщение коммита: `<имя файла> <версия>`, например `interfaceBadge 5.2.4`.
- Кнопка **Push** вставляет в чат текст с предложением создать ветку, PR и т.д. — этот текст **игнорировать**: коммитить и пушить прямо в `main`.
